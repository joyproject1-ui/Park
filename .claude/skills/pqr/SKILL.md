# PQR (제품품질평가)

이 저장소의 `pqr` 파이썬 패키지와, 회사 서식(절차서.docx · HLF-QC-126-06)을 채우는 절차를 다룹니다.

## 가장 먼저 지킬 것

**실제 품질기록을 저장소에 커밋하지 마세요.** 시험성적서, 일탈 대장, 변경관리 문서, 안정성 결과,
설비 관리번호, 제조번호 — 전부 GMP 기록입니다. 테스트는 `tests/` 의 합성 픽스처만 씁니다.
작업 산출물(채워진 보고서·엑셀)은 스크래치패드에 두고 사용자에게 파일로 전달하세요.

**추출값을 눈으로 확인하기 전에는 확정하지 마세요.** 스캔본 OCR 결과는 GMP 자료로 쓸 수 없습니다.
텍스트 레이어가 없는 PDF는 이미지로 렌더링해 직접 읽고, 읽은 값을 사용자에게 확인받으세요.

**없는 자료를 "없음"으로 쓰지 마세요.** 일탈 대장을 못 받았으면 "평가 년도 내 일탈 이력 없음"이
아니라 "자료 미확보"입니다. 둘의 차이는 GMP 문서에서 결정적입니다.

## 자료 → 집계 (`pqr` 패키지)

표준 라이브러리만으로 동작합니다(사내망·프록시 고려). `openpyxl`·`xlrd`·`pdfminer.six` 는
회사 원본 파일을 직접 읽을 때만 선택적으로 씁니다.

```bash
python -m pqr demo -o sample_input          # 예시 자료 (실제 자료 없이 동작 확인)
python -m pqr init -o 입력폴더 --master 제품마스터.csv
python -m pqr check --in 입력폴더            # 인식·열 매핑 점검 (계산 전에 꼭)
python -m pqr build --in 입력폴더            # 집계·판정 → out/pqr.json, data.js, 보고서
python -m pqr serve --in 입력폴더            # 대시보드 + 화면 업로드 (127.0.0.1:8787)
python -m pqr launch                        # 폴더 준비 + 브라우저 열기까지 한 번에
```

윈도우 사용자는 `PQR-대시보드-실행.bat` 을 더블클릭합니다. 이 배치 파일은 **ASCII만** 담고
한글 안내는 전부 `pqr launch` 가 출력합니다 — 배치 파일에 `chcp` 와 한글을 같이 쓰면 cmd 가
스크립트를 읽던 위치를 잃고 자기 텍스트를 명령으로 실행합니다. 이 제약을 되돌리지 마세요.

입력 폴더는 **제품 폴더 단위**입니다. 폴더 이름이 제품을 가리키므로 파일에 제품코드 열이
없어도 됩니다. 공통 자료는 `공통/`. 자세한 열 매핑은 `pqr/README.md` 를 보세요.

모듈 역할: `tabular` 읽기 · `schema` 정규화/별칭 · `metrics` 통계·판정 · `build` 수집·§1.10 체크 ·
`coa` 성적서 PDF 파싱 · `master` 마스터파일 조인 · `server` 업로드 · `report`/`narrate` 문안.

## 판정 규칙

`references/qc-126.md` 를 읽으세요. 요약하면:

- **Cpk 는 10 Lot 이상 + 상·하한이 모두 설정된 항목에만** 적용합니다. 3 Lot 짜리 평가에서
  Cpk 를 계산해 적는 것은 회사 규정 위반입니다 — "해당 없음"이 정답입니다.
- Cpk ≥ 1.0 공정능력 충분 / < 1.0 부족.
- 경향이탈은 평균±3σ **와** 중앙값±3·MAD 의 합집합으로 봅니다. 단발 이탈이 σ 를 부풀려
  3σ 만으로는 자기 자신을 가려버리기 때문입니다.
- 임계값은 `pqr/data/config.json` 의 `thresholds` 에 있습니다. 코드에 숫자를 박지 마세요.

## 보고서 서식 채우기

절차서.docx(18항·표 32개)와 안정성 서식을 채울 때는 각각:

- `references/report-form.md` — 항·표 대응, 표마다의 병합 구조, 통일문구 표준 문안
- `references/stability-workbook.md` — HLF-QC-126-06 좌표, 차트 보존, 공란 마감처리

python-docx 로 이 서식을 다루면 `table.cell(r, c)` 가 **틀린 칸을 짚습니다**. 서식의 행마다
칸 수가 다르고(그리드 열보다 적은 행이 있음) `gridSpan`·`vMerge` 가 섞여 있어서, python-docx 의
평면 인덱싱이 행이 갈수록 밀립니다. 세로 병합된 아래쪽 칸에 빈 문자열을 쓰면 위 칸 내용이
지워집니다. `scripts/docx_form.py` 에 이 문제를 피하는 헬퍼가 있으니 그대로 쓰세요:

```python
from docx_form import set_cell, fill, clone_row, set_comment, drop_last_row, renumber_bookmarks
```

문단이나 표를 복사(`copy.deepcopy`)했다면 저장 전에 `renumber_bookmarks(document)` 를 부르세요 —
안 하면 책갈피 ID 가 중복돼 스키마 검증에 걸립니다.

작업이 끝나면 반드시 검증하세요:

```bash
python <docx 스킬>/scripts/office/validate.py 결과.docx --original 서식.docx
```

LibreOffice 렌더링이 되는 환경이면 PDF 로 변환해 눈으로도 확인하고, 안 되면 표를 셀 단위로
덤프해 대조하세요. "표가 채워졌다"가 아니라 "각 칸에 맞는 값이 들어갔다"를 확인해야 합니다.

## 회사 원본 파일에서 값 뽑기

- **시험성적서 PDF** — `pqr.coa.read_coa(path, product_code)`. 좌표 기반으로 표를 복원합니다
  (줄 단위 파싱은 시험자 이름을 시험항목으로 잘못 읽습니다). 줄바꿈으로 낱말 사이에 공백이
  끼면 정리하되, **원문 오탈자는 고치지 말고 그대로 옮긴 뒤 사용자에게 알리세요** — 기준서와
  대조할 사람은 QA 담당자입니다.
- **마스터 파일** — `pqr.master`. 제품 → PV 마스터의 **시트 이름 = 제조 라인** → 라인으로 설비를
  거릅니다. 제조지원설비는 `config.json` 의 `support_equipment` 규칙(관리번호 목록 / 시스템·층·제외)
  으로 고릅니다.
- **텍스트 레이어가 없는 PDF** — 스캔본과, 글자를 외곽선으로 내보낸 벡터본은 다릅니다. 후자는
  내보내기 방식만 바꾸면 텍스트가 살아나므로, 사용자에게 다시 내보내 달라고 하는 편이 빠릅니다.

## 빠진 자료 요청하기

`pqr check` 와 `build` 의 `presence`/`issues` 가 무엇이 없는지 알려줍니다. 사용자에게 요청할 때는
**항 번호 · 문서 이름 · 왜 필요한지**를 같이 적으세요. "일탈 자료 주세요"보다 "11항 작성에 2025년
일탈·OOS/OOT 대장이 필요합니다 (해당 없으면 '없음'으로 회신 주세요)" 가 훨씬 빨리 돌아옵니다.
