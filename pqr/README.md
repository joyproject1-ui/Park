# PQR 자동 집계 · 보고서 생성 도구

담당자가 **제품 폴더에 자료를 올리면**, 집계 · 경향 판정 · 대시보드 데이터 · 보고서 초안까지
한 번에 만들어 주는 도구입니다.

집계 · 판정 · 보고서 생성은 **파이썬 표준 라이브러리만으로** 동작합니다 (사내망 · 프록시 환경 고려).
서술 문안 생성(`narrate`)만 `anthropic` 패키지를 선택적으로 씁니다.

---

## 담당자 작업 흐름

자료를 올리는 방법은 두 가지입니다.

**A. 화면에서 올리기 (권장)** — 대시보드를 띄우고 평가항목 칸을 눌러 그 자리에서 올립니다.

```
1. QA 담당자가 제품 폴더를 만든다     python -m pqr init  -o 입력폴더 --master 제품마스터.csv
2. 대시보드를 띄운다                python -m pqr serve --in 입력폴더
3. 담당자가 브라우저에서 칸을 눌러 파일을 올린다 → 저장 즉시 다시 집계되어 화면이 갱신됨
4. (선택) 서술 문안 초안을 붙인다     python -m pqr narrate --data out/pqr.json
```

**B. 폴더에 직접 넣기** — 파일 탐색기로 제품 폴더에 넣고 명령으로 집계합니다.

```
1. python -m pqr init  -o 입력폴더 --master 제품마스터.csv
2. 각 담당자가 자기 제품 폴더에 자료를 넣는다   (엑셀 그대로, 제품코드 열 없어도 됨)
3. python -m pqr check --in 입력폴더          자료가 제대로 인식되는지 확인
4. python -m pqr build --in 입력폴더          집계 · 판정 · 보고서
```

### 폴더 구조

```
입력폴더/
  HP-101 히알로타인 점안액 0.1%/     ← 폴더 이름이 제품을 가리킵니다
      시험성적서.xlsx
      일탈대장.xlsx
      변경불만대장.xlsx
      안정성.xlsx
  HP-201 로수바틴 정 10mg/
      ...
  공통/                            ← 제품 공통 자료
      qualification_적격성.csv
  products_제품마스터.csv            ← 루트 파일은 공통으로 봅니다
```

### 한 품목이 여러 PQR 로 갈리는 경우

제품 마스터의 **비고** 열(연간 계획서 6항의 비고)을 보고 자동으로 나눕니다.

| 비고 | 결과 |
| --- | --- |
| `미국 수출용` 만 있음 | 그 품목 자체가 미국 수출용 — 제품명에 `(미국 수출용)` 을 붙입니다 |
| `1회용 / 다회용` | 기본 품명이 다회용이고, `제품명 (1회용)` 건이 하나 더 생깁니다 |
| `미국 수출용` 이 다른 구분과 함께 | `제품명 (미국 수출용)` 건이 하나 더 생깁니다 |
| `내수용 / 수출용` | 한 보고서에서 함께 다루므로 나누지 않습니다 |

갈라진 건의 제품코드는 `QC1-5001-1회용`, `QC1-5002-미국수출용` 처럼 뒤에 구분이 붙고,
제형·그룹·마감일·담당자는 본 품목에서 물려받습니다. **마스터에 있는 행이 항상 먼저입니다.**

생산 Lot 수까지 계획서와 똑같이 맞추려면 계획서 파일을 한 번 읽히세요.

```
python -m pqr plan --doc "PQR26Plan.doc" --master 입력폴더/products_제품마스터.csv
```

계획서 표는 한 품목이 여러 줄로 적히기도 합니다(누마렌 16 Lot `1회용/다회용`, 0 Lot
`미국 수출용`). 그 줄대로 건을 나누고 각 건의 Lot 수를 넣습니다. 한 줄을 두 건이 나눠
쓰는 `1회용 / 다회용` 은 계획서도 나누지 않으므로 같은 수를 넣고 비고에 `품목 합계` 를
남깁니다 — 화면은 그 표시를 보고 Lot 수 옆에 별표를 답니다. 여러 번 실행해도 행이
늘어나지 않습니다.

제품 폴더 안 파일에는 **제품코드 열을 넣지 않아도 됩니다** — 폴더 이름에서 자동으로 채웁니다.
파일에 적힌 제품코드가 폴더와 다르면 파일 값을 쓰고 경고로 남깁니다.

폴더를 나누지 않고 한 곳에 모든 제품 자료를 넣는 방식도 그대로 동작합니다
(이때는 파일 안의 제품코드 열로 구분합니다).

## 명령어

| 명령 | 하는 일 |
| --- | --- |
| `demo` | 예시 입력 파일 생성 (`--layout tree`(기본) / `flat`) |
| `init` | 담당자가 자료를 올릴 제품 폴더와 안내문 생성 |
| `check` | 파일 인식 · 열 매핑 · 제출 현황 점검 (계산 전) |
| `launch` | 폴더 준비 · 브라우저 열기 · 서버 실행을 한 번에 (실행 파일이 이 명령을 부릅니다) |
| `serve` | 대시보드를 띄우고 **화면에서 자료를 올릴 수 있게** 함 |
| `build` | 집계 · 판정 → `pqr.json` · 대시보드 `data.js` · 보고서 |
| `narrate` | 서술 문안 초안 생성 (Claude API) |
| `report` | 저장된 데이터로 보고서만 다시 생성 |

```bash
python -m pqr demo -o sample_input          # 예시 자료로 먼저 돌려보기
python -m pqr check --in sample_input
python -m pqr build --in sample_input --today 2026-08-27
cp out/dashboard/data.js docs/pqr/data.js   # 대시보드에 연결
```

## 화면에서 자료 올리기 (`serve`)

```bash
python -m pqr launch                        # 가장 간단 — 폴더 생성 + 브라우저 열기까지
python -m pqr serve --in 입력폴더            # http://127.0.0.1:8787
python -m pqr serve --in 입력폴더 --host 0.0.0.0 --port 8787   # 사내에서 접속하게 열기
```

윈도우에서는 저장소의 `PQR-대시보드-실행.bat` 을 더블클릭하면 `launch` 가 실행됩니다
(맥·리눅스는 `PQR-대시보드-실행.command`). 실행 파일은 파이썬을 찾아 넘기는 일만 하며,
안내 문구는 모두 파이썬이 출력합니다 — 배치 파일에 한글과 `chcp` 를 함께 쓰면
cmd 가 스크립트를 읽던 위치를 잃어 내용이 깨지기 때문입니다.

- **평가항목 자료 수집** 화면에서 (a)~(v) 칸을 누르면 그 항목의 업로드 창이 열립니다.
- 마지막 칸 **(v) 0. 당해 년도 PQR word & excel** 에 EDMS 최신 양식(E-HLF-32, .docx)을 올려 두면 보고서는 그 양식으로 만듭니다. 제품마다 항·표가 다르므로 그 제품의 양식을 올리세요 — 다른 제품코드가 적힌 양식은 거부합니다.

### '보고서 작성' 이 만드는 것

자료를 다 올리고 **보고서 작성** 을 누르면 제품 폴더에 이 파일들이 생깁니다.

| 파일 | 언제 |
|---|---|
| PQR 제출용 워드 (E-HLF-32 최신 양식) | 언제나 |
| HLF-QC-126-06 안정성 시험 경향 분석 결과 (.xlsx) | 언제나 |
| Cpk 계산 파일 4종 (HLF-QC-126-08/09) | 평가 년도 생산이 **10 Lot 이상**일 때만 (QC-126) |

안정성 경향 분석은 **지난 경향표에 올해 시험 시점을 덧붙여 새로 만듭니다**. 제품 폴더에
지난 경향표(`16. 안정성시험 경향표.xlsx` 같은 채워 둔 HLF-QC-126-06)가 있으면 그 값을 그대로
이어받고, 13항 안정성 시험 자료에서 읽은 올해 시점만 더합니다. 평가 기간을 넘어선 시점(다음
해에 끝난 시험)은 넣지 않습니다 — 보고서 13.3 의 경향 범위와 같은 값이어야 하기 때문입니다.
손글씨 시험일지는 프로그램이 바로 읽지 못하므로, 새 시점이 필요하면 13항 폴더에 판독값을
`.json` 으로 두거나 나온 엑셀에 직접 채우세요(문의 목록에 알려 줍니다).
  항목에 맞는 자료 종류와 저장될 위치가 미리 표시됩니다.
- **자료 업로드** 화면에서는 제품 × 자료 표로 한눈에 보고 빠진 칸을 채울 수 있습니다.
- 올린 파일은 해당 **제품 폴더**(공통 자료는 `공통/`)에 저장되고, 저장 즉시 다시 집계되어
  화면이 갱신됩니다. 같은 종류의 자료를 다시 올리면 이전 파일을 대체합니다.
- 저장하기 **전에** 파일을 읽어 봅니다. 한 행도 적재되지 않으면 저장하지 않고,
  열 구성을 보고 "이 파일은 '안정성 모니터링' 자료로 보입니다" 처럼 알려 줍니다.
- 기본은 `127.0.0.1` 이라 그 PC에서만 접속됩니다. 사내에 열려면 `--host 0.0.0.0` 을 쓰되,
  인증 기능이 없으므로 **사내망 안에서만** 사용하십시오.
- 허용 형식은 `.xlsx .xlsm .csv .tsv .txt`, 파일당 최대 64 MB 입니다.

정적 파일로 열었을 때(`file://`)는 저장할 곳이 없으므로 업로드 버튼이 비활성화되고
실행 방법을 안내합니다.

### 항 번호 파일 — 표가 아니어도 수집 현황에 잡힙니다

파일(또는 폴더) 이름을 보고서 항 번호로 시작하면 그 항목이 '수집됨'으로 표시됩니다.

```
QC1-5007 나조린점안액/
  3. 허가증 나조린점안액.pdf        → 3항 녹색
  7. 수율현황표.xlsx               → 7항 녹색
  9.2.1 조제 완료 후/  (파일 포함)  → 9.2.1 녹색
  10.3, 10.4, 10.5 제조지원 설비.xlsx → 10.3-5 녹색
```

빈 폴더는 세지 않습니다. 제품명을 누르면(서버 모드) 그 제품 폴더가 파일 탐색기로
열리고, 수집이 100% 가 되면 '보고서 작성' 버튼이 나타납니다.

## 입력 파일 형식

파일 이름에 아래 낱말이 들어 있으면 종류를 자동으로 인식합니다.
열 이름은 한국어 · 영어 별칭을 모두 인식하며 (`배치번호` / `제조번호` / `Lot`),
`pqr/data/aliases.json` 을 두면 사내 표기를 추가할 수 있습니다.

| 종류 | 파일 이름 예 | 필수 열 | 함께 쓰면 좋은 열 |
| --- | --- | --- | --- |
| `batches` | 시험성적서 · coa | 제품코드\*, 배치번호, 시험항목 | 결과값, 규격하한/상한, 판정, 제조일, 구분단계 |
| `deviations` | 일탈대장 · oos · capa | 제품코드\*, 구분 | 관리번호, 등급, 발생일, 상태, 종결일, CAPA번호, CAPA상태 |
| `changes` | 변경 · 불만 · 회수 | 제품코드\*, 구분 | 관리번호, 발생일, 제목, 상태, 완료일 |
| `stability` | 안정성 | 제품코드\*, 시험항목, 시점 | 배치번호, 조건, 결과값, 규격하한/상한 |
| `qualification` | 적격성 · hvac · 용수 | 설비명 | 구분, 제품코드, 최종적격성일, 차기예정일, 상태 |
| `products` | 제품마스터 | 제품코드 | 제품명, 제형, 공장, 담당자, 평가기간, 마감일, 단계 |
| `stagelog` (선택) | 단계이력 | 제품코드, 단계, 진입일 | — |

\* 제품 폴더에 넣으면 제품코드 열은 생략할 수 있습니다.

날짜는 `2026-03-11` · `2026.03.11` · `2026년 3월 11일` · `20260311` · 엑셀 일련번호를 모두 읽습니다.
파일은 `.xlsx` · `.csv` (UTF-8 · CP949) 를 지원하며, 엑셀은 별도 패키지 없이 직접 읽습니다.

## 무엇을 계산하나

| 계산 | 방법 |
| --- | --- |
| 공정능력 | 시험항목별 Cp · Cpk (양측/단측 규격), 판정 기준 Cpk ≥ 1.33 양호 · ≥ 1.00 주의 |
| 규격 이탈 | 결과값이 규격하한/상한을 벗어난 배치 |
| 경향 이탈 | 평균 ± 3σ **와** 중앙값 ± 3·MAD 두 규칙. 큰 이탈값 하나가 표준편차를 부풀려 자기 자신을 숨기는 경우를 MAD 규칙이 잡습니다 |
| 안정성 경향 | 시점 대 결과값 최소제곱 기울기. 규격 쪽으로 향하고 36개월 안에 규격에 닿으면 "부정적 경향" |
| 일탈 · 변경 · 불만 | 구분별 건수, 미종결 건수, CAPA 미완결 건수 |
| 설비 적격성 | 차기 예정일 기준 기한 초과 · 90일 내 갱신 임박 |
| §1.10 자료 상태 | 제품 폴더에 자료가 없으면 `미착수`, 있으나 미결 건이 남으면 `진행 중`, 모두 확인되면 `완료` |

판정 기준은 모두 `pqr/data/config.json` 에서 바꿀 수 있습니다.

계산은 전부 결정론적입니다 — 같은 입력이면 항상 같은 결과가 나오고, 계산에 쓴
파일 이름 · 크기 · SHA-256 이 결과와 보고서에 함께 기록됩니다.

## 서술 문안 (Claude API)

집계 · 판정은 위에서 이미 끝났고, `narrate` 는 그 결과를 근거로 **문장 초안만** 만듭니다.

```bash
pip install anthropic                                  # 이 기능에만 필요합니다
export ANTHROPIC_API_KEY=...                           # 또는 ant auth login
python -m pqr narrate --data out/pqr.json --dry-run    # 전송될 내용 먼저 확인
python -m pqr narrate --data out/pqr.json
```

- **모델은 수치를 만들지 않습니다.** 모든 숫자는 `build` 결과에서 오고, 모델은 서술만 씁니다.
- **원자료를 보내지 않습니다.** 배치별 원본 값·일탈 제목이 아니라 집계 · 판정 요약만 전송합니다
  (제품당 약 2 KB).
- **보내기 전에 확인할 수 있습니다.** `--dry-run` 이 전송될 내용을 그대로 출력합니다.
- 생성된 문안에는 `review_required` 표시가 붙고, 보고서에도 "AI가 작성한 초안이며 검토·승인이
  필요하다"는 문구가 들어갑니다.

> 데이터가 사외 API 로 전송되므로, 규제 대응 문서에 사용하기 전에 사내 데이터 무결성 ·
> 정보보호 검토를 먼저 받으십시오. `narrate` 없이도 집계 · 판정 · 보고서는 완전히 동작합니다.
