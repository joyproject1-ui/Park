# PQR 관리 대시보드 (초안)

제품품질평가(Product Quality Review) 진행 상황을 한 화면에서 관리하기 위한 UI 초안입니다.
외부 라이브러리 없이 단일 HTML 파일로 동작하며, 브라우저에서 `index.html` 을 바로 열면 됩니다.

## 화면 구성

| 화면 | 내용 |
| --- | --- |
| 대시보드 — 오늘 할 일 | KPI 6종, 단계별 PQR 분포, 마감 임박 목록 |
| 제품별 현황 / 내 담당 / 일탈·OOS / 일정 / 검토·승인 | 같은 표를 조건만 바꿔 보여주는 목록 화면 |
| 평가항목 자료 수집 | EU GMP Part I §1.10 (a)~(l) 항목별 수집 상태 매트릭스 |
| 품질 이슈 경향 | 최근 12개월 일탈 · OOS/OOT · 불만 추이 (차트 + 동일 데이터 표) |
| 지연 현황 · 리드타임 | 단계별 평균 소요일 대 내부 기준, 지연 사유 분포, 지연 목록 |

제품 코드를 누르면 우측 상세 패널에서 진행 단계와 §1.10 항목별 자료 상태를 확인할 수 있습니다.

## 데이터 연결

화면의 값은 모두 `index.html` 상단의 상수에서 계산됩니다. 실제 데이터로 바꿀 때는 이 부분만 교체하면 됩니다.

| 상수 | 의미 |
| --- | --- |
| `TODAY` | 기준일. 지연·D-day 계산의 기준 |
| `PERIOD` | 평가기간 표기 |
| `STAGES` | 워크플로우 단계 (8단계) |
| `ITEMS` | EU GMP §1.10 (a)~(l) 평가항목 |
| `RAW` | 제품별 PQR 행 — `[코드, 제품명, 제형, 공장, 마감일, 단계, 담당자, 일탈, OOS/OOT, 변경, 불만, 배치수, 지연사유]` |
| `TREND` | 월별 이슈 발생 건수 |
| `LEADTIME` | 단계별 평균 소요일과 내부 기준일 |

`RAW` 를 서버 응답(JSON)으로 바꾸고 `DATA` 파생 로직을 그대로 쓰면 화면 전체가 따라 갱신됩니다.
자료 수집 상태(`checks`)는 현재 단계에 따라 코드 해시 기반으로 생성되는 임시 값이므로, 실제 연동 시
항목별 수집 상태를 그대로 넘겨주면 됩니다.

## 참고

- 화면에 표시된 제품 · 배치 · 일탈 정보는 레이아웃 검토용 **샘플 데이터**입니다.
- 평가항목 구성은 EudraLex Volume 4 Part I §1.10 (a)~(l) 을 따랐습니다.
