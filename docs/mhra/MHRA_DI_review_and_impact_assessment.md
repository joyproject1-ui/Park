# MHRA GXP 데이터 무결성 가이드 검토 및 FT/IT 시스템 영향성평가 개선 의견

**대상 문서** MHRA, ‘GXP’ Data Integrity Guidance and Definitions, Revision 1, 2018년 3월 (21쪽)
**한국어 번역본** [`MHRA_GxP_DI_Guide_2018_ko.md`](MHRA_GxP_DI_Guide_2018_ko.md)
**작성 목적** 원문 내용 검토와, 현행 FT/IT 시스템 영향성평가(Impact Assessment)에 대한 지적사항 반영 방안 정리

## 1. 문서 개요와 위상

| 항목 | 내용 |
| --- | --- |
| 발행기관 | 영국 MHRA (GLP 감시기관 GLPMA 포함) |
| 판번호 | Revision 1 (최초 발행) |
| 발행일 | 2018년 3월 |

## 2. FDA 데이터 무결성 지침과의 비교

참고사항에서 지적된 대로 MHRA 문서가 FDA 문서보다 상세합니다. 차이를 정리하면 다음과 같습니다.

| 비교 항목 | MHRA GXP DI Guide (2018) | FDA Data Integrity and CGMP Q&A (2018) |
| --- | --- | --- |
| 형식 | 원칙 + 용어 정의 + 요건 해석 (21쪽) | 18개 질의응답 (13쪽) |
| 적용 범위 | GXP 전체 | 의약품 CGMP (21 CFR 210·211·212) |
| 리스크 접근 | 데이터 중요도와 데이터 리스크를 별도 개념으로 정의하고 DIRA를 명시적으로 권고 | 리스크 기반을 언급하나 평가 방법론은 제시하지 않음 |
| 정적/동적 기록 | 정의와 예시(크로마토그램 재처리)를 명시 | 유사 개념을 다루나 정의는 약함 |
| 하이브리드 시스템 | 데이터 세트 정의·검토 강화 요구를 명시 | 별도 절 없음 |
| 감사 추적 | 리스크 기반 검토 범위, 예외 보고 방식까지 기술 | 검토 필요성 위주 |
| 클라우드·외주 | 6.20절에서 SaaS/PaaS/IaaS, 데이터 소재지, 계약 책임까지 요구 | 명시적 언급 없음 |
| 레거시 시스템 | 대체 통제와 개선 진척 입증을 조건부로 허용 | 명시적 언급 없음 |

실무 문서(SOP, 리스크 평가 양식)의 근거로는 MHRA를 기본으로 삼고, 미국 대응이 필요한 항목만 FDA Q&A를 병기하는 방식이 효율적입니다.

## 3. 영향성평가에 직접 쓰이는 핵심 조항

원문에서 시스템 영향성평가 근거로 인용할 수 있는 조항입니다.

| 조항 | 요지 | 평가서 반영 지점 |
| --- | --- | --- |
| 2.6 | 데이터 리스크·중요도·수명주기를 포함한 리스크 기반 관리 | 평가 목적 및 범위 |
| 3.4 | DIRA 수행: 프로세스 도식화 → 데이터 형식과 통제 식별 → 중요도와 고유 리스크 문서화 | 평가 절차 정의 |
| 3.6 | 노력과 자원은 환자·환경에 대한 영향에 상응 | 등급별 차등 관리 근거 |
| 4.1 | 데이터 중요도는 **그 데이터가 어떤 의사결정에 쓰이는가**로 결정 | 중요도 판정 기준 |
| 4.2 | 데이터 리스크는 **무단 삭제·수정·제외 가능성 × 탐지 기회**로 결정 | 리스크 판정 기준 |
| 4.3 | 종이 / 전자 / 하이브리드 / 기타로 데이터 생성 방식 구분. 단순 전자 시스템은 교정만으로 가능, 복잡 시스템은 의도된 용도에 대한 밸리데이션 | 시스템 분류 기준 |
| 4.4 | 영향이 낮고 상위 권한 없이는 수정 불가한 데이터는 통제 완화 정당화 가능 | 등급 하향의 근거 |
| 4.5 | 밸리데이션된 시스템도 리스크를 낮출 뿐 제거하지 못함. 사람·교육·품질 시스템까지 평가 대상 | 평가 항목 확장 |
| 4.6 | 잔여 리스크 수용, 우선순위, 단기 완화 조치 문서화 | 결론 및 CAPA |
| 6.11.1 | 정적/동적 기록 구분, 수작업 관찰은 제2자 검증 필요성을 리스크로 판단 | 기록 유형 판정 |
| 6.13 | 감사 추적 상시 활성화, 리스크 기반 검토 범위 | 통제 항목 |
| 6.16 | 개별 로그인, 공유 계정 금지, 관리자 권한과 데이터 이해관계의 분리 | 통제 항목 |
| 6.19 | 공급업체 밸리데이션 자료만으로는 불충분, 의도된 용도 기준 | 밸리데이션 범위 결정 |

## 4. 현행 영향성평가에 대한 지적사항과 개선 방향

### 4.1 지적 1 — 생산장비용 Impact Assessment와 분석기기 등급분류가 한 양식에 섞여 있음

두 평가는 목적과 판정 기준이 다릅니다.

| 구분 | 생산장비 Impact Assessment | 분석기기·컴퓨터화 시스템 평가 |
| --- | --- | --- |
| 묻는 질문 | 이 설비가 제품 품질에 직접 영향을 주는가 | 이 시스템이 만드는 데이터가 품질 판정에 쓰이는가, 그 데이터가 조작될 수 있는가 |
| 판정 축 | Direct / Indirect / No Impact | 데이터 중요도 × 데이터 리스크 |
| 대표 기준 | 제품 직접 접촉, 공정 파라미터 제어, 세척·멸균 영향 | 기록의 정적·동적 여부, 감사 추적, 계정 관리, 데이터 저장 방식 |
| 산출물 | URS·DQ·IQ·OQ·PQ 범위, 세척 밸리데이션 연계 | 밸리데이션 범위, DI 통제 항목, 검토 주기 |

두 평가를 하나의 양식으로 처리하면 어느 쪽 기준도 온전히 적용되지 않습니다. **양식을 분리**하고, 하나의 자산이 양쪽에 모두 해당하는 경우(예: 전산화된 제조 설비)에는 두 평가를 각각 수행해 결과를 연결하는 방식을 권고합니다.

### 4.2 지적 2 — 제품 접촉 여부는 QC 장비에 적용될 수 없음

제품 직접 접촉은 생산설비의 오염·교차오염 리스크를 판정하는 기준입니다. QC 장비가 접촉하는 것은 제품이 아니라 **시험용 검체**이며, 검체는 시험 후 폐기되므로 접촉 자체는 제품 품질에 직접적인 영향을 주지 않습니다.

QC 장비에서 실제 리스크는 접촉이 아니라 **그 장비가 만들어 내는 데이터가 합부 판정에 쓰인다**는 점에 있습니다. 따라서 QC 장비 평가 문항은 다음과 같이 대체해야 합니다.

| 삭제할 문항 | 대체 문항 |
| --- | --- |
| 제품과 직접 접촉하는가 | 이 장비의 결과가 원료·반제품·완제품의 합부 판정, 안정성 결론, 일탈 판정에 사용되는가 |
| 제품에 잔류물을 남길 수 있는가 | 생성되는 원 데이터가 동적(재처리 가능)인가, 정적(출력물)인가 |
| 세척 밸리데이션 대상인가 | 데이터를 무단으로 삭제·수정·재시험할 수 있는가, 그 행위가 탐지되는가 |
| 공정 파라미터를 직접 제어하는가 | 감사 추적이 있고 상시 활성화되어 있으며 사용자가 끌 수 없는가 |
| — | 개별 계정 로그인이 지원되는가, 공유 계정을 쓰고 있는가 |
| — | 결과가 다른 시스템(LIMS·ERP)으로 전송되는가, 전송이 밸리데이션되었는가 |
| — | 데이터가 장비 내부에 저장되는가, 덮어쓰기가 발생하는가, 백업 경로가 있는가 |

검체 접촉과 관련해서 남길 만한 항목은 **검체 간 캐리오버(carry-over)**뿐이며, 이는 제품 품질 영향이 아니라 **시험 결과의 신뢰성** 문제로 분류해 시험법 밸리데이션과 장비 적격성평가에서 다루는 것이 맞습니다.

### 4.3 지적 3 — USP 〈1058〉 Group A/B/C 방식의 한계

USP 〈1058〉 Analytical Instrument Qualification의 A/B/C 분류는 2008년 도입 이후 유지되어 온 방식으로, 다음 한계가 있습니다.

- 장비를 **하드웨어 복잡도**로만 나누며, 그 장비가 만드는 **데이터의 무결성 리스크**를 반영하지 않습니다.
- 소프트웨어와 하드웨어를 하나의 등급으로 묶어, 같은 Group C 안에서도 전용 워크스테이션과 서버 기반 CDS의 통제 수준 차이를 구분하지 못합니다.
- MHRA 4.3이 명시적으로 경고한 **“겉보기에 복잡성이 낮은 시스템”**(ECG, FTIR, UV 분광광도계처럼 사용자가 출력을 구성할 수 있는 독립형 장비)을 낮은 등급으로 분류해 통제에서 누락시킬 위험이 있습니다.
- 2023년 개정 〈1058〉에서 A/B/C 분류가 절대적 구분이 아니라 예시적 지침임을 명확히 하고 데이터 무결성 고려를 추가했으나, 여전히 리스크 평가 방법론을 제공하지는 않습니다.

권고안은 **GAMP 5 (2nd Edition, 2022) 소프트웨어 카테고리 + MHRA 데이터 중요도·리스크**를 주 판정 축으로 하고, USP 등급은 참고 정보로만 병기하는 것입니다.

## 5. 권고 평가 모델

### 5.1 1단계 — GXP 적용 여부

GXP 데이터를 생성·처리·보고·저장·아카이브하는가로 판정합니다. 해당하지 않으면 이후 단계를 생략하고 근거만 기록합니다. 시스템 일부만 GXP인 경우(MRP의 공급업체 승인·재고 상태 등)도 대상에 포함됩니다(MHRA 6.16).

### 5.2 2단계 — 시스템 분류 (GAMP 5)

| 카테고리 | 설명 | 예시 | 밸리데이션 기본 범위 |
| --- | --- | --- | --- |
| 1 | 인프라 소프트웨어 | OS, 데이터베이스 엔진, 네트워크 | 인프라 적격성평가, 버전 기록 |
| 3 | 비구성(Non-configured) 제품 | 펌웨어 기반 저울, pH 미터, 단순 측정기 | 의도된 용도 기준 기능 확인, 교정 |
| 4 | 구성(Configured) 제품 | CDS, LIMS, ERP, SCADA, BMS | 구성 명세, 리스크 기반 기능 시험, PQ |
| 5 | 맞춤 개발(Custom) | 자체 개발 인터페이스, 매크로, 커스텀 리포트 | 전체 수명주기 관리, 설계·코드·단위 시험 |

〔주〕 GAMP 5 2판에서 카테고리 2는 삭제되었습니다. 스프레드시트는 사용 형태에 따라 3 또는 5로 판정하며, 계산식이 포함된 워크시트는 5로 취급하는 것이 안전합니다(MHRA 6.8의 전자 워크시트 버전 관리 요구와 연계).

### 5.3 3단계 — 데이터 중요도 (MHRA 4.1)

| 등급 | 판정 기준 | 예시 |
| --- | --- | --- |
| 상 (High) | 결과가 출하 판정, 안정성 결론, 규제 제출, 환자 안전에 직접 사용 | 함량·순도 시험, 무균시험, 안정성 시험 |
| 중 (Medium) | 공정 관리와 경향 분석에 사용, 판정에 간접 영향 | 공정 중 관리 시험, 환경 모니터링 경향 |
| 하 (Low) | 참고·연구 목적, 판정에 사용되지 않음 | 개발 단계 예비 시험, 사내 참고 데이터 |

### 5.4 4단계 — 데이터 리스크 (MHRA 4.2)

무단 변경 가능성과 탐지 가능성을 함께 봅니다.

| 등급 | 판정 기준 |
| --- | --- |
| 상 (High) | 공유 계정 사용, 감사 추적 없음 또는 비활성, 로컬 폴더에 파일 저장, 사용자가 파일 삭제·이름 변경 가능, 재시험 흔적이 남지 않음, 수기 전기(轉記) 발생 |
| 중 (Medium) | 개별 계정은 있으나 권한 분리가 불완전, 감사 추적은 있으나 검토 절차 미비, 하이브리드 기록 |
| 하 (Low) | 개별 계정과 권한 분리, 상시 감사 추적, 서버 저장과 자동 백업, 시스템 간 전송이 밸리데이션됨 |

### 5.5 5단계 — 등급 판정 매트릭스

| 데이터 중요도 \ 데이터 리스크 | 리스크 하 | 리스크 중 | 리스크 상 |
| --- | --- | --- | --- |
| **중요도 상** | 등급 2 | 등급 1 | **등급 1 (최우선 개선)** |
| **중요도 중** | 등급 3 | 등급 2 | 등급 1 |
| **중요도 하** | 등급 3 | 등급 3 | 등급 2 |

| 등급 | 요구 통제 |
| --- | --- |
| 등급 1 | 완전 밸리데이션(IQ/OQ/PQ), 개별 계정과 권한 분리, 상시 감사 추적과 주기적 검토, 서버 저장·백업·복구 시험, 데이터 전송 밸리데이션, 주기적 재검토 |
| 등급 2 | 리스크 기반 밸리데이션, 개별 계정, 감사 추적 활성화, 이벤트 기반 감사 추적 검토, 백업 확인 |
| 등급 3 | 교정 또는 기능 확인, 사용 기록 관리, 주기적 점검 |

리스크가 상이면서 즉시 개선이 불가능한 경우 MHRA 4.6에 따라 **단기 완화 조치**(제2자 검증, 강화된 데이터 검토, 출력물 대조 등)를 지정하고 잔여 리스크를 경영진에 보고합니다.

### 5.6 USP 〈1058〉과의 대응 관계 (참고 병기용)

| USP 그룹 | 통상 대응 | 주의점 |
| --- | --- | --- |
| Group A (측정 기능 없는 표준 장비) | 등급 3 | 데이터를 남기지 않는 경우에 한함 |
| Group B (교정으로 관리되는 장비) | 등급 3, 데이터가 판정에 쓰이면 등급 2 | 출력물이 원 데이터가 되므로 출력물 관리 필요 |
| Group C (컴퓨터화 분석 시스템) | 등급 1~2 | 독립형 워크스테이션과 서버 기반 시스템을 구분해야 함 |

USP 그룹만으로 통제 수준을 결정하지 않고, 위 매트릭스 결과를 우선합니다.

## 6. DIRA 항목 체크리스트

MHRA 3.4의 DIRA를 시스템 단위로 수행할 때 최소한 다음 항목을 포함할 것을 권고합니다.

**데이터 수명주기 도식화**
- 데이터 생성 지점과 방식 (자동 취득 / 수기 입력 / 인터페이스)
- 처리 단계와 사용되는 사용자 정의 매개변수 (적분 파라미터, 계산식)
- 검토·승인 지점과 검토자 권한
- 보고 형태 (시스템 리포트 / 수기 전기 / 요약 보고서)
- 저장 위치, 보존 기간, 아카이브·백업 경로, 파기 절차

**기록 속성**
- 원 데이터가 무엇인지 명시 (전자 파일 / 출력물 / 하이브리드)
- 정적 기록인가 동적 기록인가
- 하이브리드인 경우 전체 데이터 세트의 정의
- 메타데이터 범위 (감사 추적, 방법 파일, 구성 설정)

**통제 상태**
- 계정 관리: 개별 로그인 여부, 공유 계정 유무, 관리자 권한 보유자와 데이터 이해관계 분리
- 감사 추적: 존재 여부, 활성화 여부, 사용자 비활성화 가능 여부, 검토 방법과 주기
- 시각 동기화와 시간대 설정
- 데이터 전송·이관: 대상 시스템, 전송 방식, 밸리데이션 여부, 전송 실패 시 절차
- 백업과 복구: 주기, 검증 방법, 복구 시험 이력
- 데이터 제외 절차: 과학적 근거 문서화, 제외 데이터의 보존 여부
- 공급업체·클라우드: 계약상 데이터 소유권, 접근 보장, 아카이브 책임, 사업 연속성

**결론**
- 데이터 중요도 등급과 근거
- 데이터 리스크 등급과 근거
- 종합 등급과 요구 통제
- 갭과 개선 조치, 우선순위, 담당자, 기한
- 잔여 리스크와 수용 근거, 승인자
- 재평가 주기와 재평가 유발 사건 (시스템 변경, 업그레이드, 공급업체 변경, 일탈 발생)

## 8. 한계와 확인 필요 사항

- MHRA 문서는 2018년 3월판이며 이후 개정되지 않았습니다. 최신 규제 동향은 EU GMP Annex 11 개정 초안(2025-07-07 의견수렴)과 Annex 22(인공지능)를 함께 확인해야 합니다. 두 문서는 이 저장소의 카탈로그에 등록되어 있습니다.
- GAMP 5 카테고리와 USP 〈1058〉 내용은 ISPE와 USP 발행 문서에 근거하며, 이 검토서에서는 요지만 인용했습니다. 사내 문서에 반영하기 전 원문 최신판을 확인하십시오.
- 본 검토서의 등급 매트릭스와 판정 기준은 MHRA 조항에 근거한 제안이며, 사내 품질 방침과 기존 밸리데이션 체계에 맞춰 조정이 필요합니다.
- 참고사항에 언급된 “FT/IT 시스템”의 정확한 범위(설비 시스템과 IT 시스템의 구분 기준)는 현행 평가 양식을 확인해야 확정할 수 있습니다. 양식을 공유해 주시면 문항 단위로 대응표를 작성하겠습니다.
