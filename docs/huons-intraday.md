# 휴온스 시간대별 매수·매도 분석 — 방법과 해석

대상: 휴온스(243070, KOSDAQ). 같은 방법이 휴온스글로벌(084110), 휴메딕스(200670)에도 그대로 적용된다.
도구: 저장소 루트의 `stock` 패키지 (`python -m stock ...`).

---

## 0. 먼저 분명히 해둘 것

이 문서에는 "휴온스는 몇 시에 사서 몇 시에 팔면 된다"는 숫자가 **적혀 있지 않다.**
그 숫자는 실제 분봉으로 아래 명령을 돌려야 나오고, 표본 기간이 바뀌면 같이 바뀌기 때문이다.
여기 적힌 것은 *무엇을 재고, 언제 그 숫자를 믿어도 되는지* 에 대한 기준이다.

또한 다음 세 가지는 원리적으로 불가능하거나 공개되지 않는다.

| 알고 싶은 것 | 실제로 구할 수 있는 것 |
| --- | --- |
| 지금 기관이 매집 중인가 | 기관·외국인 **일별** 순매수 (장 종료 후 확정) |
| 기관이 몇 시에 샀나 | 없음. 투자자별 매매동향은 일 단위로만 공개된다 |
| 지금이 오늘의 고점인가 | 사후에만 안다. 고점 시간대 **확률 분포**가 최선이다 |

시간대별로 대신 볼 수 있는 대리지표는 **프로그램매매 순매수**(KRX가 시간대별로 제공)와
**거래량 급증**이다. 이 도구는 가격·거래량만 쓴다.

---

## 1. 데이터 구하기

```bash
# (A) 네트워크가 열려 있으면 네이버 금융에서 바로
python -m stock fetch --code 휴온스 --count 2000 -o prices/huons.min.csv

# (B) 사내망·프록시로 막혀 있으면 HTS 에서 분봉을 CSV 로 내보낸 뒤 그 파일을 쓴다
#     (키움 영웅문 [0601] 분봉 → 우클릭 → 엑셀로 내보내기 등)
python -m stock slots prices/huons.min.csv
```

CSV 는 컬럼 이름을 알아서 맞춘다. `날짜/시간` 또는 `datetime` 중 하나와 `종가`만 있으면 읽히고,
`시가·고가·저가·거래량`이 있으면 전부 활용한다. CP949(엑셀 한글) 인코딩도 그대로 읽는다.

> 네이버 분봉 API 는 최근 구간만 돌려준다. **60거래일 이상**을 보려면 HTS 내보내기를 권한다.
> 표본이 30거래일도 안 되면 아래 통계는 사실상 의미가 없다.

### 분봉 시각 표기 주의

네이버·대부분의 HTS 는 09:00~09:01 봉을 **09:01** 로 찍는다(끝 시각 표기). 그대로 시간대에
넣으면 개장 구간이 한 봉씩 밀린다. 도구 기본값 `--stamp end` 가 이걸 되돌려 놓는다.
이미 시작 시각으로 찍힌 데이터라면 `--stamp start` 를 준다.

## 2. 네 가지 명령

| 명령 | 답하는 질문 |
| --- | --- |
| `slots` | 어느 시간대가 평균적으로 오르고 내리는가 |
| `matrix` | 몇 시에 사서 몇 시에 팔았을 때가 가장 나았는가 |
| `peak` | **고점이 몇 시에 찍히는가, 그 뒤 얼마나 되돌리는가** |
| `report` | 위 세 개를 마크다운 한 파일로 |

"기관이 올려놓고 파는 타이밍"에 직접 대응하는 것은 `peak` 이다.

```bash
python -m stock peak prices/huons.min.csv --surge 3.0
```

`--surge 3.0` 은 *시가 대비 고가가 +3% 이상 터치한 날*만 골라 그날들의 고점 시간대를 따로 센다.
평범한 날을 섞으면 급등일의 패턴이 평균에 묻히기 때문이다. 휴온스처럼 재료(임상·수주·자사주)에
움직이는 종목은 `--surge` 를 2.0~5.0 사이로 바꿔가며 분포가 흔들리는지 보는 편이 낫다.

## 3. 표 읽는 법

### `slots` — 시간대별 손익

* **평균bp** : 그 시간대의 평균 수익률. 1bp = 0.01%.
* **승률** : 오른 날의 비율. 평균이 +인데 승률이 50% 아래면 *가끔 크게 오르고 자주 조금씩 빠지는*
  구간이다. 실제로 타기는 훨씬 어렵다.
* **t값** : 평균이 0 과 다르다고 볼 근거의 세기. 도구는 `10거래일 이상 && |t| ≥ 2` 일 때만
  '유의' 표시를 붙인다. **표시가 없으면 그 시간대 편향은 없다고 보는 게 맞다.**
* **거래비중** : 그 시간대에 몰린 거래량 비율. 한국 시장은 보통 개장 30분과 마감 30분이 크고
  점심때가 가장 얇은 U자형이다. 거래비중이 낮은 구간의 통계는 체결이 안 되는 값일 수 있다.
* **폭bp** : (고가−저가)/시가. 그 시간대의 변동성. 폭이 큰 구간은 평균이 좋아도 손절이 자주 걸린다.

### `peak` — 상승 타이밍 프로파일

* **고점확률** : 당일 고가가 이 시간대에서 나온 날의 비율. 여기가 "빠져나갈 자리"의 후보다.
* **저점확률** : 당일 저가가 나온 비율. "들어갈 자리"의 후보.
* **다음구간 연속상승** : 이 시간대가 올랐을 때 다음 시간대도 오른 비율.
  **50% 근처면 모멘텀이 없다** — 오르는 걸 보고 따라 사면 진다는 뜻이다.
  60%를 꾸준히 넘는 구간이 있어야 추격 매수가 성립한다.
* **고점을 저점보다 먼저 찍은 날** : 이 비율이 60%를 크게 넘으면 "올려놓고 빠지는" 날이
  실제로 우세하다는 뜻이고, 그때는 **아침 강세를 사는 게 아니라 파는 쪽**이 통계적으로 맞다.
* **시가→고가 / 고가→종가** : 위로 얼마나 열어주고 얼마나 되돌리는지. 되돌림이 상승폭의 절반을
  넘으면 고점 근처에서 못 팔면 남는 게 없는 구조다.

## 4. 언제 이 숫자를 믿으면 안 되는가

1. **표본 60거래일 미만.** 시간대가 14개면 한 칸당 데이터가 60개도 안 된다. 우연이 이긴다.
2. **'유의' 표시가 없는 구간을 골랐을 때.** 매트릭스에서 가장 좋아 보이는 칸은 거의 항상
   우연히 좋았던 칸이다. 14×14 칸을 다 보면 그중 몇 개는 저절로 좋아 보인다(다중검정).
3. **비용 미반영.** 이 도구의 숫자에는 수수료·거래세·슬리피지·호가 스프레드가 **없다.**
   휴온스 정도 거래대금에서 한 호가 스프레드는 왕복 20~40bp를 쉽게 먹는다.
   평균 +30bp짜리 시간대 전략은 비용을 넣으면 사라진다. **최소 +80~100bp는 나와야**
   실전에서 남을 여지가 생긴다.
4. **레짐 변화.** 실적 발표, 유상증자, 지수 편입/편출, 대주주 이슈 전후로 일중 패턴은 바뀐다.
   `--from` / `--to` 로 기간을 반 갈라 두 구간에서 같은 결론이 나오는지 반드시 확인한다.

```bash
# 전반부와 후반부가 같은 이야기를 하는지 (가장 중요한 검증)
python -m stock peak prices/huons.min.csv --to 2026-06-30
python -m stock peak prices/huons.min.csv --from 2026-07-01
```

두 결과가 다르면, 그건 패턴이 아니라 잡음이다.

## 5. 수급과 붙여 보기

가격만으로는 "기관이 올렸다"를 확인할 수 없다. 확인하려면 일별 투자자별 매매동향을 붙여야 한다.

1. KRX 정보데이터시스템(data.krx.co.kr) 또는 네이버 금융 종목 화면에서
   **기관·외국인 일별 순매수**를 받는다.
2. `peak` 이 뽑은 '급등일' 날짜와 그 날짜의 기관 순매수를 대조한다.
3. 급등일에 기관이 순매수인데 다음날 순매도로 돌아서는 패턴이 반복되면,
   그때 비로소 "올려놓고 판다"는 가설에 근거가 생긴다.
   급등일과 기관 순매수가 무관하다면, 오르는 원인은 기관이 아니라 다른 데 있다.

## 6. 결론에 해당하는 한 문단

일중 시간대 편향은 **존재하더라도 대개 수십 bp 단위**이고, 그 크기는 개인 투자자의 거래비용과
비슷하거나 그보다 작다. 그래서 이 분석의 현실적인 쓸모는 "몇 시에 사서 몇 시에 판다"는 매매법을
만드는 것이 아니라, **이미 사기로/팔기로 결정한 주문을 어느 시간대에 집행할지** 를 고르는 데 있다.
같은 매매를 하더라도 고점확률이 높은 구간에서 팔고 저점확률이 높은 구간에서 사면,
연간 수십 bp는 아낀다. 그게 이 표에서 꺼낼 수 있는 가장 정직한 이득이다.

*이 문서와 도구는 정보 제공용이며 투자 자문이 아니다. 매매 판단과 그 결과는 전적으로 본인 책임이다.*
